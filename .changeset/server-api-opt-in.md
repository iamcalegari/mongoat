'@iamcalegari/mongoat': minor
---

Stop configuring MongoDB's Stable API behind an environment variable, and let the constructor's driver options actually reach the driver.

**`serverApi` is now an explicit choice, never Mongoat's.** `Database#connect()` used to inject `serverApi: { version: v1, strict: true, deprecationErrors: true }` whenever `process.env.NODE_ENV === 'production'`. `strict: true` makes the server reject every command outside Stable API v1, so an application using Atlas Vector Search could not run under the very value production is expected to carry — it failed with `MongoServerError: $vectorSearch is not allowed with 'apiStrict: true' in API Version 1` (`code: 323`, `codeName: APIStrictError`). `createSearchIndex` and `listSearchIndexes` are outside the Stable API as well, so index-provisioning scripts broke the same way. Tying the driver's API contract to an environment variable also made the behavior invisible: nothing in the application's own code revealed that `NODE_ENV` changed it. Mongoat now sets no `serverApi` at all, and no default pins the version either — declaring `apiVersion: 1` unconditionally would change the wire contract for consumers that work today and would require server 5.0+. Opt in through the constructor instead: `new Database({ dbName, serverApi: { version: ServerApiVersion.v1, strict: true } })`. Anyone who was relying on strict mode under `NODE_ENV=production` has to add that option back explicitly.

**Constructor options are no longer discarded.** The constructor stored `config`, but `connect()` built the driver's options object from scratch — only `uri`, `username` and `password` were read, elsewhere. Every other `MongoClientOptions` field (`maxPoolSize`, `appName`, `tls`, `compressors`, …) was silently dropped, and `ignoreUndefined` only appeared to work because the value hardcoded in `connect()` happened to match what applications passed. Precedence is now explicit: Mongoat supplies defaults and the constructor's config overrides them, key by key. `ignoreUndefined: true` stays the only default and can now be switched off. The four Mongoat-specific fields (`uri`, `dbName`, `username`, `password`) are stripped before the rest is forwarded, because the driver refuses keys it does not know (`MongoParseError: option uri is not supported`); a compile-time exhaustiveness gate keeps that list in sync with `DatabaseConfig`.

**`ServerApiVersion` and `ServerApi` are re-exported** from the package root, so opting into the Stable API does not require a direct `mongodb` install.
